# 积分与非现金充值

积分账户由当前身份和租户自动关联。用户不需要执行“开户”；余额读取失败与真实零余额分开处理，不能用一个假0掩盖失败。

## 管理员发放

后台积分页先选择当前租户收款成员，再填写正整数积分和审计原因，核对后确认。`GET /v1/admin/identity/members` 的 `member_id` 是成员关系标识；收款字段必须选择该行的 `user_id`，不能用关系标识代替。分页搜索只筛选当前已加载页，不声明检索了整个租户。

`POST /v1/admin/billing/credit-grants` 是非现金发放，不发起真钱支付，也不是管理员手工替代实际用量扣费。管理操作依赖当前Product会话及平台管理员资格；公开的契约说明不授予普通用户、User API Key或普通OAuth App此权限。

正文为闭集：

| 字段 | 含义 |
| --- | --- |
| `funding_id` | 首次提交生成的永久UUID v4；恢复时保持原值。 |
| `subject_id` | 当前租户收款成员的`user_id`。 |
| `amount_credits` | 正整数积分字符串，1–9223372036854；不是micros或浮点数字。 |
| `reason` | 非空审计原因，最多500个Unicode字符。 |
| `effective_at` | 首次提交时冻结的UTC毫秒时点，恢复时不重新采样。 |

`Idempotency-Key`随首次确认冻结，正文没有tenant、操作者、余额或价格字段；这些事实由服务端核实。具体必填字段、格式和错误状态以[API参考](/reference/v1/generated/administration)为准。

## 结果与恢复

只有正式201回执中的`account_id`、`grant_id`、`journal_id`确认发放；它不包含当前余额，不能由此伪造余额展示。超时、取消、连接断开或不合法回执均不证明没有发放。

刷新不自动发POST。结果未确认时保留原完整正文、`funding_id`、时间与幂等键，人工核对后只显式重试原请求，不生成新键重充。先前未知、后来收到拒绝，也不说明先前没有记账；切换管理员或租户会停止旧界面读写并保留原命令，恢复须确认原主体。

实际用量扣分由正式Agent用量证据及Billing计量结算负责，而不是这个充值表单。整数扣分、余额和不可变流水以对应部署的真实整链验收为准；本页和生成参考不代替正常环境、模型／工具执行或资金验证。

## 价格与单次积分预算

计价配置与充值相互独立：充值增加可用积分，计价决定真实用量的结算。平台管理员可调用以下正式接口；公开参考不授予调用资格，也不表示普通客户端持有内部服务凭据。

| 接口 | 作用 |
| --- | --- |
| `GET /v1/admin/billing/metering/pricing` | 在同一快照中读取最新已发布rate与policy；两者可独立为空，也可尚未生效。不是当前有效报价或未知命令未提交的证明。 |
| `POST /v1/admin/billing/metering/rate-revisions` | 发布有明确来源、核实时间、生效时间和最多64条费率的不可变修订。 |
| `POST /v1/admin/billing/metering/policy-revisions` | 发布冻结倍率、费用到积分转换和`max_attempt_credits`单次整积分预算的不可变策略。 |

两类发布的正文都是`publication_id`、`reason`和`configuration`闭集，需原`Idempotency-Key`；正文最大1MiB、JSON最多12层。预算、费率有理数和revision均为十进制字符串，客户端不使用浮点数换算。具体格式、范围和错误状态以生成参考为准；owner固定的协议版本和取整规则不作为表单输入。

每条费率必填`model_revision`，其`id`和`content_digest`指向同一份精确System不可变模型修订。模型显示名、请求模型名、别名或Key句柄不能替代该身份，也不自动推导商业账户或价格。同一修订在一份完整费率配置只对应一个显式商业映射和币种；输入／输出等桶可分别配置，不同修订可复用同一商业映射。发布后按新修订替换，不为旧无绑定费率注入默认值；配置发布本身不验证消费资格或代表模型已经调用。

201回执的`kind`、`revision`、`content_digest`、`published_at`和`effective_from`共同确认发布；客户端核对`kind`和原生效时间，不用最新列表猜提交成功。首次确认应保存完整原命令、key和当前身份，持久写入并读回成功后才派发。刷新不自动POST；超时或回执未知只显式恢复原publication/key/configuration/reason/时间，后续拒绝不证明先前没有发布。切换管理员或租户停止旧请求，原未知记录保留；读取latest/null或其他revision不清除它。

执行时应先按单次预算预占，再以同一attempt的已核实真实用量和冻结配置统一一次向上取整到整积分；分片、重试和重复回执不逐片扣分。确认未派发才释放，已核实用量在预算内结算并释放余量；用量未知或超预算保留预占和证据、待核对并停止同Run后续派发，不补零、不截金额、不自动补扣或重发。单次预算不是供应商绝对成本保证。计量执行和资金效果需另外完成真实链路验收，文档及配置发布不代替该证据；真钱支付不在此流程内。
