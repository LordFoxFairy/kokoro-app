# 登录与登录恢复

## 用户操作

从产品登录入口输入现有 Kokoro 账户。登录完成返回原来的产品页面。认证协议由系统内部处理，不要求用户填写 scope、回调地址或 token。

OAuth 回调或授权服务失败时，产品显示统一结果页。页面不会自动重复登录，也不会更改已有内容；用户可选择返回登录或首页。重新登录是新的交易，过期回调链接不作为登录入口。

## 登录表单地址（本地候选）

协议入口只用于跳转，密码表单停留在 `/auth/sign-in?flow=…`。表单刷新和错误密码重试保留这个短地址，不在页面、表单 action 或反馈跳转中显示原始协议参数。该引用需要本浏览器的 HttpOnly 证明，不是登录凭据；复制到另一个浏览器不授予访问权限。

同一表单刷新只回收已观察到的本交易旧证明，其他登录标签不受影响。每次渲染的证明和错误反馈均独立绑定交易；成功后只清本交易。原签名参数仍由服务端逐字交给 IAM 验证，没有新增登录服务、独立后台会话或旧 POST 兼容入口。当前通过真实 Next／Redis 专项验收，正常运行尚未切换；状态以当前交付记录为准。

## 内部维护

- App 拥有 Product 会话及同源登录页面，IAM 拥有身份认证和 OAuth client/resource。不要用跨库写入修复权限。
- `invalid_scope` 是环境或版本配对故障，不是密码错误。核对当前 App 的 `OIDC_SCOPE`、运行 IAM discovery 以及正式 Product Web client/resource 的已登记 scope。
- 账户会话读取／撤销及姓名保存分别依赖 `iam:account-session.read`、`iam:account-session.revoke`、`iam:account-profile.write`。使用 IAM 既有 scope read／extend 管理入口，先读取和核对旧状态，按该 owner 的演进顺序处理；不删 App 所需权限或给所有 client 放开权限。
- 顶层 HTML 登录失败返回固定 `/auth/sign-in/failed`；API 继续返回失败 status 和脱敏 JSON。回调的 code、state、issuer 描述和 cookie 不转入结果页或文档。
- 通过 issuer/state/PKCE/nonce 绑定后才创建正式会话。失败不伪造成功、不恢复旧 state、不清理其他并行登录的 cookie；未知 token 结果不自动重发。

## 登录会话连续性（本地候选，正常配对待验）

初始登录只从原生验签成功的 ID token 保存 issuer 的 `sid`，并绑定同次 Auth.js account 的原 ID token 和 subject。续期亦验证新 ID token 的签名、issuer、client、期限及原 subject／sid；相同用户不代表相同登录会话。整个 token 与 JWKS 读取共用5秒预算，失败不重复兑换旋转凭据，仍按原待定会话清理／CAS处理。

`sid` 只在服务端加密 HttpOnly Product cookie 内，不进入公开 session JSON、URL或日志。旧缺失 sid 的 cookie 直接失效，不回填或兼容；正常激活需重新走正式登录，不清业务数据。此绑定只约束登录／续期，Agent Run不存用户token、不负责续期，也不据此新增 Billing OAuth 旅程。

## 验收要求

新登录成功并回原目标；错误／过期／重复回调只显示产品结果；API 失败仍失败；较新登录和原会话不被旧回调破坏；刷新结果页不新增认证请求。环境配对和页面验收需要分别有证据，服务健康或旧会话成功不替代新登录验收。

本页维护已实现交互及验收口径，未声称本轮所有登录、Skills、后台或 MCP 已完成。机器配置、会话与原始网络材料不进入仓库。

## 多标签交易：已加载并完成正常双密码回归

- 每个登录启动表单拥有签名返回意图和独立 CSRF cookie；每次提交又拥有独立 Auth.js state／PKCE／nonce namespace。同一浏览器的两个表单和两个返回目标不共用临时槽位。
- IAM 密码表单每次渲染各有独立短期 proof，同一个签名链接的两个首次渲染也不覆盖。绑定通过后才原子消费；错误 query、issuer 或 proof 不烧掉合法表单。
- 已消费终态只清自己的临时 cookie；未证明失败不清其他交易或正式会话。过期密码表单停在产品结果页，不自动重发凭据，用户显式发起新的登录。
- 一个浏览器仍共享一个正式账户会话，不是每标签多账号。Consent／invitation 流程本次不改。

真实 Next／Redis 已验证冷启动两个返回目标、callback 正反序与错 proof 后原交易可继续。正常双密码的失败根因是 IAM 对同一 Session 普通属性变化做了隐式整行 CAS；保留原谓词、身份和到期／撤销校验后，两个原生续接均成功。2026-10-21 正常 App76326e5／IAM1c4209b 已实测两标签各回产品目标，技能设置与另一标签的历史正文可读；不把此结果等同于所有登录交互或全部模块完成。

## 退出登录

产品退出后，账号退出确认使用 Kokoro 中文页面。点击“退出登录”才向身份服务提交正式确认；打开、刷新或返回首页都不会自动确认，也不会删除任务和资料。返回首页不恢复此前已退出的应用会话。

身份服务仍核对当前浏览器会话及短期确认凭据。过期、错误或未确认结果显示“退出暂未完成”，不伪造成功、不自动重试。后台原生API的失败状态保持，页面的失败参数只选择展示，不授予退出权限。交互页保留精确同源Origin，失败页不含确认表单。

2026-10-21 已正常加载，并实测正式退出确认、密码重登及历史回读；窄屏和键盘可用，范围及证据见CURRENT。未声称与Manus退出交互逐像素一致。
