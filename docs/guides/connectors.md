## 重复服务器URL

当前私有MCP注册返回“此服务器URL已添加”时，请使用现有连接器或更正URL后明确保存；名称和备注不丢失。若之前已有网络未知结果，重复URL不代表原请求失败，仍沿原命令恢复，不自动新建。自定义MCP和通过URL添加共用此规则；它不改变账号连接状态或服务端唯一性约束。

## 2026-10-24 私有MCP试用

已连接且当前可用的私有MCP详情，“试用一下”会进入新任务并预填测试提示词、选中该连接器；仍需用户明确发送才执行。它不是重新Prepare或授权。原提交结果未确认、任务仍在运行或连接资格不足时保留当前任务并显示反馈；原连接准备的恢复入口独立保留。设置与外层广场的管理入口共用此行为。完整四创建、图标、更多传输及Skills状态见CURRENT，不能据此认为已全部完成。

# 连接器：连接、续期与托管包

## 用户路径

从插件／连接器目录选择提供方，或在设置的连接器页添加自定义 MCP。远程 MCP 通过服务地址和相应授权连接，**不要求上传 ZIP**。连接、授权、读取工具声明与实际执行工具是不同动作；目录或详情可见不代表已经启用或获准执行。

OAuth 在提供方授权窗口完成；Product 和管理后台沿用同一个产品登录会话，不为后台另建 OAuth 登录。浏览器拦截弹窗时，应先允许本次授权窗口，再显式重试；关闭窗口不当作授权成功。错误或待核实结果保持可恢复，页面不自动反复重发命令。

## 可用性与续期

页面消费 owner 返回的 `availability`，不以安装／启用状态猜测：

| 值 | 含义 |
| --- | --- |
| `available` | 当前资格可用；实际调用仍要核验授权和精确声明。 |
| `refresh_required` | 需要续期，不表示用户应重新登录产品。 |
| `refreshing` | owner 正在协调续期。 |
| `reauthorization_required` | 需要用户明确重新授权。 |
| `unavailable` | 当前连接不满足可用条件。 |

打开页面、刷新列表或 GET 详情不触发令牌续期、重新连接或工具执行。Platform 在受控使用前协调 OAuth 续期；App 只显示资格和既有恢复操作。令牌刷新后权限范围缩小，不会偷偷改写原命令确认的版本；原命令可以明确失败，用户核对当前事实后才发起新的操作。

超时或结果未知不等于未提交。恢复沿用原请求、版本和幂等键；成功回执重放不重新授权或重复发现声明。页面不生成新的命令来掩盖未知结果，也不把通用前置条件失败伪装成服务返回格式错误。

## 准备连接结果待核实（候选，尚未正常生效）

仅Prepare增加非秘密的浏览器恢复日志：关闭/重开保原请求，不自动连接。若显示“需先核验状态”，明确点击只重新读取同一服务器及连接器；读取成功不是连接成功。之后另一次点击“重试原请求”才沿原版本和幂等键请求正式回执。关窗会退休核验资格，再打开需重新核验；过期或身份冲突不因读取成功而解锁。

恢复存储读取失败时保留原意图并提供重读，不降级为新请求；不在此日志保存密钥、URL或令牌。旧浏览器从未保存的命令不会被新机制追认。此候选已做隔离原生存储验证，正常页面/原Prepare回执仍待验，以CURRENT为准。

## 管理后台的可选托管包

“能力枢纽 → 托管包发布”面向需要分发软件包的 MCP，不是所有连接器的必经步骤。后台负责 ZIP 上传、Storage 扫描与不可变版本发布；提供方目录管理、个人连接和 live runtime 分别有独立事实。发布包不自动启用提供方，不安装到其他用户，也不执行工具。

连接器服务的 API Key、OAuth client secret 和令牌不写进技能正文、普通文档、日志或截图。界面只显示已有资格或配置状态；配置敏感值使用正式表单，不能用别人的连接或平台机器身份代替个人授权。

## 工程与验收边界

- App 只经同源 adapter 访问 BFF；Platform 拥有 MCP 控制面，IAM 拥有身份，Storage 拥有包字节与扫描，Agent 拥有实际运行。
- Browser-private 请求、错误与当前固定生成物以 [API 契约](../API_CONTRACT.md) 和 [MCP 组件归属](../../src/ui/mcp/INDEX.md) 为准；它们不是新增的公开 Developer API，也不宣称复制了 Manus 私有后端。
- 当前代码已用真实 Next／BFF HTTP、IAM PostgreSQL／Redis 和 Platform PostgreSQL 验证：正规登录、授权码／PKCE、自然过期、一次受控刷新、范围收缩后原 CAS 失败、显式新命令及回执重放；另验证无效 refresh token 不盲目重发、显式 Reconnect 可恢复授权。AS/MCP 服务是隔离夹具，仅发现声明，零 `tools/call`。
- 这份 HTTP 验收不是浏览器水合、正常租户续期、页面重授权入口可达或 Agent runtime 执行证明。正常包上传／扫描／发布另有真实验收，不重复造样本。最新证据与未完成项统一见 [当前事实](../CURRENT.md)。
- 当前 Agent／IAM／Platform 另完成隔离的运行发现验证：正式签名及 Resolve／Acquire、精确包下载、标准 SDK stdio 发现，以及撤销后拒绝再次领取。只领取 discovery 资格，没有调用工具。Storage 控制面与对象服务仍是夹具，未覆盖 Agent lease／journal、正常页面或实际执行，不等同完整工具运行验收。

私有 MCP 显式重连入口已实现：原 Prepare 结果待核实或重放过期时，仍可独立发起 Reconnect，原请求／版本／幂等键保持不变。配置层 HTTP 及组件回归已验证；当前正常浏览器的 OAuth 自然过期续期、invalid_grant 后从详情／配置显式重连，以及正常组合中的 stdio 发现／回收旅程仍待验收，不以新建连接替代恢复。
